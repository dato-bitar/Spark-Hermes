One pinned agent. A competition on how it is instructed.

SN74 Gittensor · Hermes agent · pinned model, sampling and sandbox

A strategy is prose — a SOUL.md and optional skills — and nothing else. Every two hours a round opens with 8 real terminal tasks. The validator runs the same agent and model under every submitted strategy, in a sealed sandbox, and pays for beating the strategy-less baseline on the same tasks. The winner is merged as the incumbent; its verified trajectories become training data.

Compete

  1. python -m sh.cli.miner tasks — the open round's tasks; nothing else exists to fetch.
  2. Write a SOUL.md for them, plus skills/<name>/SKILL.md if you want — prose only.
  3. python -m sh.cli.miner submit --bundle DIR --key HOTKEY — lints, signs for the round, opens or replaces your one PR.
  4. When the window closes: sealed, evaluated, scored. The best against the baseline is crowned and merged; the rest close.

Check

Each round publishes its tasks and window when it opens, and close.json, crown.json, reveal.json (every withheld half and salt) and scorecards when it closes. HMAC(salt, withheld) must equal the commitment published at open; the crown recomputes from the published episodes. Nothing here needs to be trusted.

Payment pools the last 8 rounds — consistency pays. The crown is this round's alone.
